# Machine learning e ONNX

MQL5 può eseguire modelli **ONNX**, un formato di scambio per reti neurali. Il flusso tipico:
1. Addestra il modello in Python (per esempio una LSTM o una CNN).
2. Esporta in ONNX.
3. Includi il file nell'EA (come risorsa) e usa le funzioni ONNX di MQL5 (`OnnxCreate`, `OnnxRun`; controlla i dettagli nella documentazione ufficiale aggiornata).
4. Ricostruisci in MQL5 **esattamente** le stesse feature e la stessa normalizzazione.

### Regole che evitano gli errori classici

- **Normalizzazione solo sul training**: media e deviazione standard si calcolano sul solo insieme di addestramento e si salvano. Calcolarle sull'intero dataset introduce informazione dal futuro.
- **Feature causali**: solo dati disponibili alla chiusura della barra.
- **Etichette senza sovrapposizioni** con il test (cura nelle finestre future usate come target).
- **Stessa ordinazione e forma degli input** in Python e in MQL5.
- **Parità numerica**: a parità di input, l'output in Python e in MQL5 deve coincidere.
- **Walk-forward e costi** sempre, come per qualunque strategia.

```python
import torch

model.eval()
x = torch.randn(1, 30, 5)

    model, x, "model.onnx",

```

```python
import numpy as np
import onnxruntime as ort

sess = ort.InferenceSession("model.onnx")
y_o = sess.run(
    None, {"x": x.numpy()})[0]
y_t = model(x).detach().numpy()
print(np.abs(y_o - y_t).max())
```

L'ultima verifica deve stampare un valore trascurabile, per esempio inferiore a 0,0001. Gli stessi dati di prova vanno poi passati al modello dentro MQL5 per confrontare i risultati.

### Aspettative realistiche

Ricorda il Capitolo 12: i prezzi hanno un rapporto segnale/rumore bassissimo. Un modello che prevede la direzione della prossima candela raramente batte i costi. Regole di buon senso:
- un modello deve battere, **fuori campione e al netto dei costi**, una semplice linea di base (per esempio la strategia a regole senza ML);
- un uso più realistico è come **filtro** su un segnale già definito: il modello stima se *quella* operazione ha buone probabilità di raggiungere +2R prima di −1R (idea nota come *meta-labeling*), e si salta quando la probabilità è bassa;
- più il modello è complesso, più dati e più cautela servono.
