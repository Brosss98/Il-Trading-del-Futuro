# Laboratorio: il segnale e il motore di test in Python

Usiamo le funzioni `ema`, `rsi`, `atr` (Capitolo 5) e `stats` (Capitolo 9). Si assume un DataFrame `df` con `open`, `high`, `low`, `close`, `ema50`, `ema200`, `rsi`, `atr`.

### Il segnale

```python
def signals(df):
    """Segnale long a fine candela."""
    up = df["ema50"] > df["ema200"]
    up = up & (df["close"] > df["ema200"])
    r = df["rsi"]
    cross = (r.shift(1) < 45) & (r >= 45)
    return up & cross
```

### Il motore di test minimo

```python
def backtest(df, sig, rr=2.0, k=2.0,
             max_bars=40, cost_r=0.05):
    """Risultati in R. Solo long."""
    res, i, n = [], 0, len(df)
    while i < n - 2:
        if not sig.iloc[i]:
            i += 1
            continue
        e = df["open"].iloc[i + 1]
        risk = k * df["atr"].iloc[i]
        stop = e - risk
        tp = e + rr * risk
        last = min(n, i + 1 + max_bars)
        out, j = None, i + 1
        while j < last:
            if df["low"].iloc[j] <= stop:
                out = -1.0
                break
            if df["high"].iloc[j] >= tp:
                out = rr
                break
            j += 1
        if out is None:
            j = last - 1
            c = df["close"].iloc[j]
            out = (c - e) / risk
        res.append(out - cost_r)
        i = j + 1
    return res
```

Cose da notare:
- l'ingresso è `open[i+1]`, mai la chiusura del segnale;
- lo **stop** viene controllato prima del target nella stessa candela;
- `cost_r` sottrae un costo in R a ogni operazione (spread e slippage);
- dopo un'uscita, `i = j + 1`: una sola posizione alla volta;
- il motore **ignora i gap** (se il prezzo apre sotto lo stop, assume comunque l'uscita allo stop): è ottimistico. Nel Capitolo 16 lo miglioriamo.

### Il test di sanità su dati casuali

Prima di usare dati reali, verifica che il tuo motore **non trovi vantaggi dove non ce ne sono**. Su una serie casuale (random walk) nessuna strategia dovrebbe avere vantaggio, e il risultato deve essere vicino a zero, meno i costi.

```python
import numpy as np
import pandas as pd


def fake_df(n=3000, seed=3):
    rng = np.random.default_rng(seed)
    ret = rng.normal(0, 0.005, n)
    c = 100 * np.exp(np.cumsum(ret))
    o = np.r_[c[0], c[:-1]]
    s = np.abs(rng.normal(0, 0.003, n))
    h = np.maximum(o, c) * (1 + s)
    l = np.minimum(o, c) * (1 - s)
    return pd.DataFrame({
        "open": o, "high": h,
        "low": l, "close": c})


df = fake_df()
df["ema50"] = ema(df["close"], 50)
df["ema200"] = ema(df["close"], 200)
df["rsi"] = rsi(df["close"])
df["atr"] = atr(df)
df = df.dropna()
res = backtest(df, signals(df))
print(len(res), stats(res))
```

**Come leggerlo.** Su dati casuali l'expectancy attesa è vicina a zero, meno i costi. Ma una singola serie di circa 35 operazioni oscilla di ±0,25R solo per caso: in 60 serie di prova un risultato di +0,3R è comparso nel 5% dei casi e uno di +0,12R in quasi un caso su tre. Per un controllo affidabile ripeti il test su molte serie e accorpa le operazioni, come nel codice qui sotto: con oltre mille operazioni l'errore standard scende a circa 0,03R. Se l'expectancy aggregata resta nettamente positiva (per esempio oltre +0,1R), hai quasi certamente un bug, tipicamente un lookahead. È uno dei controlli più economici ed efficaci che esistano.

Per accorpare 50 serie casuali e stimare anche l'errore standard:

```python
def sanity(n_seeds=50):
    allr = []
    for s in range(n_seeds):
        d = fake_df(3000, seed=s)
        d["ema50"] = ema(d["close"], 50)
        d["ema200"] = ema(d["close"], 200)
        d["rsi"] = rsi(d["close"])
        d["atr"] = atr(d)
        d = d.dropna()
        allr += backtest(d, signals(d))
    r = np.array(allr)
    se = r.std(ddof=1) / np.sqrt(len(r))
    print(len(r), round(r.mean(), 3),
          round(se, 3))


sanity()
```

Con 50 serie lo script stampa circa 1.450 operazioni, un'expectancy media di circa −0,05R (i costi) e un errore standard intorno a 0,03R: il risultato è compatibile con zero meno i costi, come deve essere.
