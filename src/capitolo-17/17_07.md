# Il codice: una pipeline con guardrail

Questa pipeline riceve la **risposta testuale** dell'LLM, la valida, applica i controlli di rischio e chiede l'approvazione. Non invia ordini: l'invio al broker dipende dalla sua API e va aggiunto con grande cautela.

### Parte 1: la proposta

```python
import json
import math
from dataclasses import dataclass


@dataclass
class Proposal:
    symbol: str
    side: str
    entry: float
    stop: float
    target: float
    reason: str


def parse_proposal(text):
    """Valida il JSON dell'AI."""
    d = json.loads(text)
    if "none" in d:
        return None
    p = Proposal(
        symbol=str(d["symbol"]),
        side=str(d["side"]).lower(),
        entry=float(d["entry"]),
        stop=float(d["stop"]),
        target=float(d["target"]),
        reason=str(d.get("reason", "")),
    )
    if p.side not in ("buy", "sell"):
        raise ValueError("side")
    vals = (p.entry, p.stop, p.target)
    ok = all(math.isfinite(v) and v > 0
             for v in vals)
    if not ok:
        raise ValueError("numeri")
    return p
```

### Parte 2: limiti, controlli e dimensione

```python
LIM = {
    "syms": {"EURUSD", "XAUUSD"},
    "risk": 0.5,
    "dayloss": 2.0,
    "orders": 3,
    "rr": 1.5,
    "dev": 0.3,
    "minstop": 0.1,
    "maxlev": 5.0,
}


def check(p, st, px):
    """Controlli deterministici."""
    L = LIM
    if st["halt"]:
        return False, "kill switch"
    if px <= 0:
        return False, "prezzo non valido"
    if p.symbol not in L["syms"]:
        return False, "simbolo"
    if st["dl"] >= L["dayloss"]:
        return False, "perdita giorno"
    if st["n"] >= L["orders"]:
        return False, "troppi ordini"
    dev = abs(p.entry - px) / px * 100
    if dev > L["dev"]:
        return False, "prezzo lontano"
    if p.side == "buy":
        ok = p.stop < p.entry < p.target
        risk = p.entry - p.stop
        rew = p.target - p.entry
    else:
        ok = p.target < p.entry < p.stop
        risk = p.stop - p.entry
        rew = p.entry - p.target
    if not ok or risk <= 0:
        return False, "livelli errati"
    if risk / px * 100 < L["minstop"]:
        return False, "stop troppo vicino"
    if rew / risk < L["rr"]:
        return False, "R:R basso"
    return True, "ok"


def size(p, eq):
    """Unità dal rischio fisso."""
    dist = abs(p.entry - p.stop)
    return eq * LIM["risk"] / 100 / dist
```

### Parte 3: la pipeline

```python
def process(text, st, px, eq, approve):
    """L'AI propone, il codice dispone."""
    try:
        p = parse_proposal(text)
    except Exception:
        return "scartata: formato", None
    if p is None:
        return "nessuna proposta", None
    ok, why = check(p, st, px)
    if not ok:
        return "scartata: " + why, None
    qty = size(p, eq)
    if qty * px / eq > LIM["maxlev"]:
        return "scartata: leva", None
    if not approve(p, qty):
        return "rifiutata dall'umano", None
    st["n"] += 1
    return "ok", (p, qty)


st = {"halt": False, "dl": 0.0, "n": 0}
txt = ('{"symbol": "EURUSD",'
       ' "side": "buy", "entry": 1.0850,'
       ' "stop": 1.0820,'
       ' "target": 1.0910,'
       ' "reason": "test"}')
print(process(txt, st, 1.0851, 10_000,
              lambda p, q: True))
```

**Che cosa succede con l'esempio.** I livelli sono coerenti (stop 1,0820 sotto l'ingresso 1,0850, target 1,0910 sopra), il rapporto rischio/rendimento è 2 (0,0060 / 0,0030) il prezzo è vicino al mercato, lo stop non è troppo vicino e la leva effettiva (circa 1,8 volte il conto) è sotto il limite: la proposta passa. La dimensione è 10.000 × 0,5% / 0,0030 ≈ 16.667 unità. Nell'esempio l'approvazione è simulata con `lambda p, q: True`; in uso reale la funzione deve **chiedere conferma a una persona**.

**Provalo.** Cambia lo stop in 1,0880 (sopra l'ingresso di un acquisto): ottieni `scartata: livelli errati`. Porta `"symbol"` a `"BTCUSD"`: `scartata: simbolo`. Metti `st["halt"] = True`: `scartata: kill switch`. Con `"stop": 1.08499` (quasi uguale all'ingresso) ottieni `scartata: stop troppo vicino`: senza questo controllo la dimensione supererebbe i 5 milioni di unità, cioè una leva di oltre 500 volte.

**La difesa dalla prompt injection.** Se un testo malevolo convince l'LLM a proporre «compra 100 lotti», la proposta non contiene nemmeno il campo della quantità: la dimensione la calcola `size`, dal rischio fisso. Il codice limita il danno anche quando l'AI è stata ingannata, purché i limiti coprano anche i casi estremi: lo stop minimo e la leva massima servono proprio a questo.
